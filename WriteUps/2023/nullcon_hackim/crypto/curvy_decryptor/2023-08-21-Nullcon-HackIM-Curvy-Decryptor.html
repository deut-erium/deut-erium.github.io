Analysing curvy_decryptor.py

indeed look like a standard curve P-256 (note that a = -3 is equivalent to a = p - 3)
So there doesnt appear to be any standard weakness based on weak curve parameters.
The private key d_a is initialized to be per-instance system-random 128 bit number
And the Public key P_a is simply G*d_a

Encryption

The msg is encoded as the x coordinate of the point, the corresponding y is found so as to find the point on the curve to generate the point m
A secure random number d_b in range (0 - curve order) is generated as the nonce, The points G*d_b and m + (pubkey * d_b) are returned

Analysing ec.py

Looking closely at the ECPoint class, one would note that on the initialization of the point with arbitrary x, y coordinates, it works as usual and doesnt check whether the supplied x, y satisfy the curve equation y2=x3+ax+bmod  py^2 = x^3 + ax + b \mod py2=x3+ax+bmodp

This leads to an interesting vulnerability aka Invalid Curve Attack

Which can be noted by the facts that

  1. The point addtion of two points PPP and QQQ over the curve y2=x3+ax+bmod  py^2 = x^3 + ax + b \mod py2=x3+ax+bmodpif P≠QP \ne QP=Q is independent of both the curve parameters aaa and bbb
  2. The point doubling i.e P=QP = QP=Q is just dependent on PPP and QQQ and aaa but not on bbb again

This means that the group addition operation is independent of the parameter bbb, the number of points in the group of some point PPP is just dependent on PPP and aaa but independent of bbb

So if we choose a curve C′C'C′ with parameter b′b'b′ and pick a valid point P′P'P′ on it, and run the point addition over the original curve CCC, the order of point P′P'P′ when used on CCC will be the same as order of point P′P'P′ when used on C′C'C′

This implies that we are not stuck with the original prime order of P-256, but we can vary b=−3b = -3b=−3 such that the order of the curve C′C'C′ has small factors. We can then easily find points P′P'P′ with those small factors as their order by using the fact that -
If G′G'G′ is the generator of C′C'C′ with order o=f1f2f3...fno = f_1f_2f_3...f_no=f1​f2​f3​...fn​, the point G′∗(o/f1)G' * (o/f_1)G′∗(o/f1​) will have the order f1f_1f1​

Once we have sufficient number of small orders, we can take a chinese remainder theorem over them to recover the original private key d_a
